# KPI Operation — ARRIVE (React + Vite)

داش بورد منفصلة تقرأ من **نفس Apps Script Web App** الخاص بالداش التشغيلية (نفس البيانات)، عن طريق action جديد: `?action=clientMonthly`.

## القاعدة
- نسبة النجاح للعميل في الشهر = (التسليم + «رفض الاستلام و تم دفع الشحن») ÷ إجمالي الشحنات. «رفض الاستلام و رفض الدفع» لا يُحسب.
- للشهر المقاس: متوسط التسليمات = متوسط آخر 3 شهور قبله، للعملاء الموجودين في الـ3 شهور + الشهر المقاس فقط.
- الفرق بالنقاط المئوية: ≥ 3 مقبول، ≥ 5 المطلوب، ≥ 7 ممتاز، أقل من 3 غير مقبول.

## التشغيل
```bash
npm install
npm run dev      # أو npm run build للنشر على Vercel
npm test         # اختبارات منطق الحساب
```
معاينة الشكل ببيانات تجريبية: `/?demo=1`.

## مطلوب قبل ما تشتغل ببيانات حقيقية
1. انسخ `Code.gs` المحدّث (فيه `getClientMonthlyPayload`) في Apps Script واعمل **Deploy جديد** (Manage deployments ← Edit ← New version).
2. الداش بتقرأ من الملخصات المحفوظة (`DASHBOARD_SUMMARY`) فقط: لازم الشهور الأربعة (3 سابقة + المقاس) يكون ليها Snapshot.
3. الـ Deployment لازم يكون «Anyone» عشان المتصفح يقدر يقرأه.
4. افتح «مراجعة تصنيف الحالات» في الداش وتأكد إن نص «دفع الشحن» اتصنف صح.

## ملاحظة عن الباك إند
`apps-script-Code.gs` نسخة من `Code.gs` الخاص بالداش التشغيلية (فيها action `clientMonthly`). هي اللي بتتنشر في Apps Script، ومش جزء من تطبيق React.

## الأقسام (قايمة جانبية)
- **المؤشرات الرئيسية:** كروت كل مؤشر (نسبة التسليم، First Attempt) مع رابط «عرض التفاصيل».
- **نسبة التسليم:** الكروت، ملخص الإدارة، كارت النسبة (الرسم + جدول الفروع)، النتيجة شهر بشهر، تفصيل العملاء، ومراجعة تصنيف الحالات. جدول الفروع يحتاج `Code.gs` المحدّث (`withBranches=1`).

- **First Attempt:** نفس صفحة نسبة التسليم لكن النجاح = «تسليم من أول محاولة» فقط (بدون أي رفض). التقييم: +3 مقبول، +6 المطلوب، +10 ممتاز. يحتاج `Code.gs` المحدّث (الرقم الرابع في كل خلية).

### إضافة مؤشر جديد
1. أضف مقياسًا في `METRICS` في `src/lib/quality.js` (التسمية، دالة النجاح، حدود التقييم).
2. أضف عنصرًا في `SECTIONS` في `src/App.jsx` (id, metric, icon): يظهر تلقائيًا في القايمة وفي «المؤشرات الرئيسية» وبصفحته الكاملة.
