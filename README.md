# KPI Operation — ARRIVE (React + Vite)

لوحة مؤشرات للإدارة. **مستقلة تمامًا عن الداش بورد التشغيلية**: باك إند خاص بيها (مشروع Apps Script منفصل) بيقرأ بس من نفس الشيتات ولا يكتب فيها ولا يغيّر أي حاجة في الداش القديمة.

## المعمارية
```
Google Sheets (DASHBOARD_SUMMARY — ملخصات الداش التشغيلية، قراءة فقط)
        ▲
backend/Code.gs   ← مشروع Apps Script جديد وWeb App خاص بيه (التارجت بيتخزن في إعداداته هو)
        ▲
React (هذا المشروع) ← VITE_API_URL
```

## نشر الباك إند (مرة واحدة)
1. افتح script.google.com ← **New project** (مشروع جديد، مش مشروع الداش القديمة).
2. الصق محتوى `backend/Code.gs` واحفظ.
3. شغّل الدالة `doGet` مرة من المحرر ووافق على الصلاحيات (قراءة الشيتات من نفس حسابك).
4. **Deploy ← New deployment ← Web app** — *Execute as: Me* — *Who has access: Anyone* ← Deploy.
5. انسخ رابط `…/exec` وحطه في Vercel كمتغير `VITE_API_URL` (أو في ملف `.env` محليًا).
6. للتأكد افتح `…/exec?action=ping` ثم `…/exec?action=clientMonthly&months=October`.

## تشغيل الواجهة
```bash
npm install
npm run dev     # أو npm run build للنشر على Vercel
npm test        # اختبارات الحساب والباك إند
```
معاينة الشكل ببيانات تجريبية: `/?demo=1`.

## الأقسام
- **المؤشرات الرئيسية:** كروت كل مؤشر (نسبة التسليم، First Attempt) مع رابط «عرض التفاصيل».
- **نسبة التسليم:** النجاح = تسليم + رفض الاستلام مع دفع الشحن. التقييم: +3 مقبول، +5 المطلوب، +7 ممتاز.
- **First Attempt:** النجاح = تسليم من أول محاولة فقط (بدون أي رفض). التقييم: +3 / +6 / +10.
- **العملاء:** أداء كل عميل (اختيار المؤشر من الأعلى).
- **جودة البيانات (منفصلة):** تغطية الشهور، فحص رد السيرفر، تصنيف الحالات، فحص أسماء العملاء.
- **الإعدادات:** تارجت كل فرع لكل مؤشر (٪)، يتخزن على السيرفر ويظهر في جدول الفروع مع «محقق / لم يتحقق».

كل مؤشر: نفس العملاء (الموجودين في الـ3 شهور السابقة + الشهر المقاس)، ومتوسط آخر 3 شهور، والفرق بالنقاط المئوية.

### إضافة مؤشر جديد
1. أضف مقياسًا في `METRICS` في `src/lib/quality.js` (التسمية، دالة النجاح، حدود التقييم).
2. أضف قسمًا `kind: 'metric'` في `SECTIONS` في `src/App.jsx`.
